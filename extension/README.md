# Bookmark Brain — Chrome extension

Pairs with either edition of the server — this repo's own self-hosted
single-tenant app (the `server.js` one directory up), or the hosted
multi-tenant edition at
[github.com/technocon/bookmark-brain-cloud](https://github.com/technocon/bookmark-brain-cloud)
— to add:

- **Search from the toolbar** — semantic search without opening the web app.
- **One-click save** — save the current tab, or right-click any page/link →
  "Save to Bookmark Brain". Fetches, embeds, and clusters it immediately.
- **Direct bookmark import** — reads your Chrome bookmarks via
  `chrome.bookmarks`, no manual export/upload step.

## Load it (unpacked, for development)

1. Make sure the server is running (`npm start` in the project root — default `http://localhost:3300`).
2. Open `chrome://extensions`.
3. Turn on **Developer mode** (top right).
4. Click **Load unpacked** and select this `extension/` folder.
5. Click the Bookmark Brain icon in the toolbar. If the status dot is red, open **Settings** and confirm the server URL.

## Pointing it at a different server

Open the extension's Settings (⚙ in the popup, or right-click the icon →
Options), enter the server URL, and click Save. The manifest only grants
permission for `localhost`/`127.0.0.1` up front — pointing it at anything
else (a LAN address, or a hosted domain) triggers a one-time Chrome
permission prompt, which is normal and expected.

## Self-hosted vs. hosted (multi-tenant)

The extension detects which kind of server it's talking to by requesting
`/api/meta`:

- **Self-hosted** server has no such route (404) → no accounts, no sign-in
  UI, works exactly like a single-user local tool. This is the only mode
  that existed before multi-tenant support was added, and it's unchanged.
- **Hosted/multi-tenant** server returns `{ requiresAuth: true }` → the
  popup shows a sign-in/create-account form before anything else, and the
  Settings page shows an Account card (sign in, subscription status,
  manage/subscribe buttons). The session token is stored per-server-URL in
  `chrome.storage.local`, sent as `Authorization: Bearer <token>` on every
  request — no cookies involved, so popup/background/options contexts all
  share it without any cross-origin cookie complications.

## Files

- `manifest.json` — Manifest V3 config.
- `popup.html` / `popup.js` / `popup.css` — the toolbar popup: sign-in (if required), search, save current tab.
- `options.html` / `options.js` / `options.css` — server URL config, account/billing (if required), bulk Chrome-bookmarks import.
- `background.js` — service worker: right-click context menu ("Save page" / "Save link").
- `shared.js` — server URL + auth token storage and the `/api/meta` mode-detection helper, shared by all three contexts above.
- `icons/` — generated by `generate-icons.js` (a dependency-free PNG encoder — the project already hit native-module build issues with `better-sqlite3` on this Node version, so icon generation avoids any image library too).
